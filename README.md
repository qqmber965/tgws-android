# TG WS Proxy Android – Python core 1.11.4

Экспериментальный Android-проект для **оригинального ядра Flowseal tg-ws-proxy 1.11.4** из приложенного архива. Он **не является** сборкой crim50n, amurcanov или Regstar2. Исходный каталог `proxy/` скопирован **без изменений** из `tg-ws-proxy-1.11.4.zip`. Сверка SHA-256 – `SOURCE_SHA256.txt`.

**Статус:** исходный проект подготовлен, синтаксис и работа Python-адаптера на localhost проверяются локально. Реальная сборка APK, установка на устройство и маршруты WSS/Cloudflare на Android **не проверялись**. Никаких гарантий работоспособности в мобильной сети нет. Проект предназначен для пробной сборки и диагностики.

## Требования

- Android 8.0+ (`minSdk=26`), 64-битный ARM (`arm64-v8a`), Telegram.
- Для сборки: JDK 17, Gradle 8.12.1, Android SDK Platform 35, Python 3.13, интернет для Gradle и pip.
- Python в APK предоставляется [Chaquopy 17.2](https://chaquo.com/chaquopy/doc/current/android.html). Для Android выбирается `cryptography==42.0.8`, т.к. именно для него есть предварительно собранный пакет Android; API, использованные оригиналом, сохранены.

## Получение APK через GitHub Actions

1. Распаковать проект, создать **свой** репозиторий на GitHub и загрузить туда содержимое папки (включая `.github/workflows/android-apk.yml`).
2. Открыть вкладку **Actions → Build Android APK → Run workflow**. При первом запуске GitHub может предложить включить Actions.
3. После успешной сборки открыть выполненный workflow и скачать артефакт `TG-WS-Proxy-1.11.4-Android-arm64-debug`. В ZIP будет `app-debug.apk` и его SHA-256.
4. Перенести `app-debug.apk` на телефон и установить. Это отладочная APK с автоматически созданной подписью для пробного использования, не release APK.

Альтернативно: открыть папку в Android Studio, дождаться загрузки Gradle и выполнить **Build → Build APK(s)**. При установленном `gradle` можно выполнить `gradle :app:assembleDebug`.

## Использование

1. Открыть приложение. Настройки по умолчанию максимально близки к версии ПК: `127.0.0.1:1443`, 4 WS-соединения на DC, Cloudflare и H2 включены, DC2/DC4 `149.154.167.220`.
2. При необходимости ввести те же Cloudflare-домены и IP, что используются на ПК, затем **Сохранить и запустить**.
3. Дождаться состояния **Работает на 127.0.0.1**. Нажать **Открыть прокси в Telegram** или **Копировать ссылку прокси** и подключить MTProto-прокси.
4. Не отключать приложение через принудительную остановку; разрешить работу в фоне в настройках Android. На некоторых устройствах потребуется исключение из оптимизации батареи. После смены сети перезапустить прокси.

Включённый `HTTP/2` может требовать дополнительных маршрутов Cloudflare, недоступных у конкретного мобильного оператора. Для диагностики попробуйте отключать/включать H2 и менять пул (`0` отключает прямые WebSocket).

## Как это устроено

- `app/src/main/python/proxy/` – исходный код версии 1.11.4 **без изменений**.
- `app/src/main/python/mobile_runner.py` – адаптер остановки/запуска `asyncio` для Android.
- `app/src/main/java/.../ProxyService.java` – foreground service c уведомлением и wake lock.
- `app/src/main/java/.../MainActivity.java` – настройки, секрет, старт/стоп, ссылка Telegram.
- `.github/workflows/android-apk.yml` – сборка APK в облачной среде GitHub Actions.
- `tests/test_android_adapter.py` – тест запуска, принятия TCP-соединения на loopback и штатной остановки.

Сервис слушает **только 127.0.0.1**, не открывает порт в локальную сеть и не создаёт системный VPN. Секрет хранится в приватных настройках приложения. Для нового клиента придётся сохранить/применить ссылку заново. Обновления устанавливаются отдельно, автоматическое обновление не реализовано.

## Ограничения и предупреждения

- Это **новый package ID** `io.github.tgwsproxy.python114`. Старые Android-приложения остаются установленными; **не запускайте одновременно** два прокси, прослушивающих один порт 1443.
- Android ограничивает фоновые процессы. Foreground service и частичный wake lock не гарантируют непрерывную работу на всех прошивках.
- Неизвестно, проходит ли трафик через актуальные ограничения сети: рабочий ПК и телефон могут иметь разные маршруты, DNS, доступность Cloudflare и Telegram DC.
- В версии Python 1.11.4 TLS-проверка и альтернативные маршруты перенесены как есть; модель доверия совпадает с оригиналом. Не используйте неизвестные CF-домены.
- Это не полная замена ПК-приложения: отсутствуют системный трей, графики, автозапуск после перезагрузки, автоматический сброс пулов после смены сети, логи в интерфейсе.
